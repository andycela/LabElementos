Concurrencia y Multitarea en el microcontrolador RP2040Este repositorio documenta una práctica enfocada en implementar y validar mecanismos de multitarea en el chip RP2040, explorando dos estrategias complementarias: simulación virtual orientada a eventos por tiempos en Wokwi y procesamiento paralelo real empleando ambos núcleos en hardware físico (Raspberry Pi Pico).⚙️ ¿De qué trata la práctica?El proyecto integra la lectura de señales analógicas, indicación visual mediante LEDs, comunicación por puerto serie, un sistema de latido (heartbeat) y gestión interactiva de alarmas con reconocimiento de usuario (acknowledge).El concepto central de la multitarea aquí aplicada busca evitar el bloqueo del procesador, permitiendo atender múltiples rutinas de manera intercalada o verdaderamente simultánea.💻 Simulación Interactiva en WokwiEn este entorno, la concurrencia se simula ejecutando distintas tareas dentro de un bucle principal unificado, gestionadas mediante intervalos de tiempo específicos:Lectura de sensores (ADC): Cada 20 ms.Lectura de pulsador: Cada 50 ms.Interfaz y latido (heartbeat): Cada 500 ms.Reporte por monitor serie: Cada 1000 ms.Lógica de Umbrales y AlertasEl valor analógico del potenciómetro se transforma a una escala porcentual (0% a 100%) para definir tres escenarios operativos:Menor al 50%: Estado NORMAL (LED indicador activo).Entre 50% y 74.9%: Estado WARNING (LED de advertencia).Mayor o igual al 75%: Estado ALARM (LED parpadeante).Reconocimiento (ACK): Al presionar el botón físico, el parpadeo de la alarma se detiene y pasa a un encendido fijo mientras persista la condición crítica. El heartbeat se encarga de evidenciar visualmente que el flujo del programa nunca se congela.⚡ Implementación en Hardware (Raspberry Pi Pico)La prueba sobre la tarjeta física explota la arquitectura Dual-Core nativa del RP2040 para lograr paralelismo real:Núcleo 0 (Core 0): Administra el ciclo principal cada 1000 ms, gestiona un LED indicador y monitorea variables globales.Núcleo 1 (Core 1): Ejecuta una rutina rápida cada 100 ms, conmuta un LED secundario e incrementa un contador compartido.Sincronización: Se implementa un mecanismo de exclusión mutua (lock) para proteger el acceso concurrente al contador y evitar conflictos de memoria.📊 Resumen de Comportamiento y UmbralesNiveles de Activación[ 0% ] -------- ( NORMAL ) -------- [ 50% ] -------- ( WARNING ) -------- [ 75% ] -------- ( ALARM ) -------- [ 100% ]
